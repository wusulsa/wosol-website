24 نوفمبر2026؛ wosol.net فقط. هذه مواصفة اعتماد، وليست تكاملًا منفذًا أو مختبرًا بإرسال حي.

## التوصية
حفظ الواجهة الحالية، واستخدام Zoho Forms كمصدر حقيقة ثم Zoho Flow لإشعار GA4 بقبول سجل جديد للموافقين على القياس فقط. لا CRMجديد ولا تغيير مسار البريد أو تسجيل الطالبات. يلزم قبل البناء فحص الاتصالات والحقول الموجودة وإعادة استخدامها؛ توفرالخطةوالصلاحياتوتكلفةالمهاملمتُفحصبعد.
لماذا ليسWorkflowالموقع؟ المتصفح يغادر إلىHTMLRecords/submit ولا يحصل على إقرارقبول. قواعدFormWorkflowيمكنهاتصفيةالسجلات لكنهاوحدهالاتحققإسنادGA4ومنعالتكرار. لا ClientScript/Blueprint/Approvalلحلهذا. Flowهوطبقةالتكاملالمقترحة؛ وظيفةDelugeصغيرةفقطإذااحتاجتنقية/تحققلايمكنبالقواعد.

## المسار
1. بعد موافقة القياس فقط يقرأالموقعمعرفاتGA4الحالية؛ لا ينشئ معرفًا من البريد/الهاتف. إرفاقسياقالقياسالتقنيبالطلب يتطلباعتمادحقولمخفيةوخريطةالحقول.
2. Trigger: New form entry للنموذجينWOSOLTransportQuote وWOSOLContact بعدحفظالسجل. لاTriggerعلىزرالإرسال أوform_start.
3. تحققمنالنوعوالموافقةوالنطاقوالوقتوسياقالجلسة. الطلبغيرالموافق أوالناقصيحفظفيZohoولايرسلGA4؛ تعطلالقياسلايعطلاستقبالالطلب.
4. منعالتكرار بمفتاح(form ID + entry ID + event name) داخلي. يجبإثباتوجودحجزذري/قيدفريد قبلالتفعيل؛ بحثثمإنشاءغيركافللتزامن. لا نعدبexactly-once؛ المهلةبعدإرسالGA4حالةملتبسةتحتاجمراجعة، لاإعادةعمياء. لايرسلentryIDإلىGoogle.
5. إرسالأحداثمحدودةعبرMeasurementProtocol؛ السرعلىالخادم/اتصالآمن فقط، لافيالمتصفحأوGitHub. HTTP2xxلايثبتقبولGA4للمخطط؛ يلزمتحققالمخططوالنتيجةلاحقًا.
6. سجلالحالةداخليpending/sent/failed/ambiguous ومراجعةالإدارة؛ دونمحتوىالطلبفيالسجلاتالتقنية. لاإعادةإرسالالنموذج.
