# معالجة أداء الرئيسية العربية — 20 أكتوبر 2026

## النتيجة

نُشر التحسين على الرئيسيتين دون تغيير التصميم أو المحتوى أو النماذج. تحسن LCP العربي من 3.013 ثانية في قياس التشخيص إلى 2.408 ثانية، لكن الدرجة الإجمالية بقيت 94 بسبب ارتفاع Speed Index في العينة الأخيرة. الإنجليزية 99 وLCP نحو 2.04 ثانية. لا نعتبر التراجع مغلقًا بالكامل حتى يستقر الأداء العربي عبر عينات إضافية وبيانات الاستخدام الفعلية.

## التشخيص والإصلاح

- أثبت PageSpeed أن عنصر LCP هو صورة المقدمة، وليس عنوان الصفحة. في التشخيص: تأخر اكتشاف المورد 820ms وتنزيله 1110ms؛ تحميل CSS والخطوط ظهر كذلك ضمن السلسلة الحرجة.
- ضغط نسختي WebP مع إبقاء الأبعاد والشفافية والتكوين: 1600px من 144986 إلى 57282 بايت (نحو60.5% أقل)، و1000px من70160 إلى30030 بايت (57.2% أقل). فُحص تطابق قناة الشفافية ومظهر الصورة. هذه إعادة ضغط مع فقد محدود للجودة، وليست ضغطًا بلا فقد.
- إضافة responsive preload مطابق تمامًا لـsrcset/sizes الفعليين، بعد تعريف viewport حتى لا يختار متصفح الجوال حجمًا غير مناسب قبل معرفة العرض. صُحح هذا الترتيب خلال التنفيذ وأُضيف فحص آلي له.
- تحميل مبكر لملف خط العنوان العربي Tajawal800 فقط؛ الخط نفسه والأوزان والألوان والتنسيق لم تتغير.
- الاحتفاظ بالأصول القديمة للرجوع، وأسماء جديدة للصور لتجاوز النسخ المخزنة. لم يلزم تفريغ CDN: تطابق53/53 موردًا وصفحة عامة مع المصدر المحلي بعد آخر نشر.

## المتبقي

1. استقرار Speed Index العربي والتحقق من أثر الحركة المعتمدة عليه؛ لم تُلغَ الحركة أو يُعدّل التصميم للحصول على درجة أعلى.
2. فصل CSS الحرج/تصغير CSS تحسين إضافي يحتاج تحققًا بصريًا مستقلًا قبل النشر؛ لا يحذف CSS بناءً على قياس الصفحة الرئيسية وحدها.
3. متابعة Core Web Vitals الميدانية بعد توفر بيانات كافية؛ لا توجد حاليًا أدلة تسمح بإعلان تحسن جميع الزوار.
4. تبقى بنود اعتمادية Zoho والاحتفاظ بالبيانات وقبول خدمات Google والفهرسة كما في سجل المعلقات، خارج نطاق هذا التغيير.
