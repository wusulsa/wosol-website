## تفعيل القياس في الجلسة التالية

1. فتح حساب GA4 الصحيح والتحقق من Web Stream الخاص بـ`https://www.wosol.net`؛ لا تنشئ خاصية مكررة. راجع واعتمد الإفصاح الخاص بالتحليلات والخصوصية قبل التفعيل، ثم سجل Measurement ID في `js/measurement-config.js` بعد التحقق.
2. مراجعة إعدادات Enhanced Measurement وتعطيل القياس الآلي للنماذج وتغييرات العنوان/History في هذا التنفيذ لتجنب التكرار والتقاط روابط تحتوي على بيانات. مراجعة Google Signals وUser-provided data قبل التفعيل. لا توجد آلية إرسال للنص الحر أو الاسم أو الجوال أو البريد في أحداثنا.
3. إجراء اختبار DebugView بعد موافقة المستخدم الاختيارية وعلى النطاق الرسمي. الأحداث: `page_view`، `form_start`، `contact_phone_click`، `contact_whatsapp_click`، `contact_email_click`، `email_request_accepted`.
4. `email_request_accepted` يعني قبول مزود البريد فقط، وليس وصول الطلب إلى CRM أو تأهيله أو عقدًا. لا يستخدم كدليل تسليم CRM. حدث `generate_lead` والتحويلات المؤهلة مؤجلان حتى معالجة H03/H06.
5. ربط المصدر والحملة بالحقول الموجودة في Zoho أولًا، ثم Workflow للتوزيع والمتابعة. لوحة Zoho Analytics تحتاج بيانات طلبات مؤهلة وعقود قبل حساب تكلفة الاكتساب.
6. لا تُرسل Query String أو Hash أو Referrer كامل في أحداث التنفيذ الحالي. توثيق مصدر الحملات ونسب الإسناد التفصيلية مؤجل حتى تحديد آلية جمع آمنة وربط CRM؛ لا ندعي اكتمال Attribution.

## المواد والقرارات الناقصة

- حساب Google الذي يدير الموقع والملفات الحالية، Measurement ID، ورابطا ملفي جدة والرياض إن وُجدا.
- العنوان الدقيق والزيارات المسموحة وساعات العمل لكل موقع حقيقي؛ ساعات تشغيل الرحلات ليست بالضرورة ساعات استقبال المكتب.
- صور مقصورة ومقاعد وأحزمة ومخارج ومركبة أصلية بجودة عالية، دون وجوه أو لوحات أو أسماء عملاء غير معتمدة للنشر.
- نسخ منفصلة للشهادات، جهة الإصدار، النطاق وتواريخ الصلاحية، وصلاحية عرضها للعامة. لا يُنشر ملف الشركة كاملًا.
- اعتماد ساعات التواصل ومسؤول التصعيد وزمن الرد الفعلي، والترتيبات القياسية للبديل، قبل تحويلها إلى وعود منشورة.
